# Подготовка к защите Assignment 6

## Краткое объяснение проекта

Движок анализирует дерево метаданных fintech-проекта. Пять элементов описывают исходный код, тесты, конфигурацию, зависимости и каталоги. Каждый элемент реализует `ProjectElement.accept(ProjectVisitor)`. Пять Visitor выполняют независимые операции. Проект демонстрирует паттерн Visitor; он не считывает Java-файлы и не запрашивает базу уязвимостей.

Откройте `Main`, `ProjectVisitor`, `SourceCodeFile`, `TraversingVisitor` и тест `dispatchesEveryElementToItsExactOverload`. Покажите запуск `mvn clean verify`, затем `java -jar target/smart-code-inspection-1.0.0.jar`. Сравните провальный fintech-пример и успешный release-ready.

## Двойная диспетчеризация

Первый динамический вызов — `element.accept(visitor)`: выбирается реализация конкретного элемента. В `SourceCodeFile.accept` тип `this` известен компилятору как `SourceCodeFile`, поэтому выбирается перегрузка `visit(SourceCodeFile)`. Второй динамический вызов выбирает реализацию этой перегрузки у фактического Visitor. Java не выбирает перегрузки по runtime-типу аргумента: эту задачу решает типизированное место вызова внутри `accept`.

Если убрать `accept` из интерфейса, клиент не сможет вызвать его через `ProjectElement`; аннотации `@Override` элементов также перестанут соответствовать контракту. Если заменить это вызовом `visitor.visit(element)`, код не скомпилируется: перегрузки `visit(ProjectElement)` нет. Добавление такой общей перегрузки само по себе не восстановит выбор по конкретному типу.

**Predict:** новый Visitor не меняет элементы или интерфейс `ProjectVisitor`.

**Explain:** существующие `accept` уже вызывают все нужные перегрузки; `TraversingVisitor` обеспечивает обход каталогов и пустые реализации листьев.

## Частые вопросы

* Почему Directory не обходит детей сам? Чтобы каждый `accept` только выполнял диспетчеризацию, а Visitor мог определять порядок и глубину обхода. Нельзя одновременно обходить детей в Directory и Visitor: это удвоит обработку.
* Почему Compliance не проверяет отсутствие тестов сразу в `visit(SourceCodeFile)`? Тестовый каталог может быть посещён позже. Решение вычисляется из накопленных production-модулей и множества протестированных модулей при запросе результата.
* Почему новый Visitor для нового проекта? Экземпляры накапливают состояние. Повторный обход тем же экземпляром повторно добавит данные.
* Можно ли пройти дерево любой глубины? Нет. Проверены 200 уровней; очень глубокое дерево может переполнить стек. Для неограниченной глубины нужен обход с явным стеком, сохраняя `accept` для диспетчеризации.
* Visitor или Strategy? Strategy заменяет один алгоритм; Visitor определяет операцию над несколькими конкретными типами через двойную диспетчеризацию. Их можно применять вместе.
* Где OCP? Новый TechnicalDebtVisitor не изменил элементы. Добавление нового типа элемента показывает границу OCP в этой архитектуре.

Живая защита выполняется лично. Перед сдачей убедитесь, что можете объяснить каждый расчёт и самостоятельно изменить перегрузку и соответствующий тест.
